# 통신·용량 최적화 — 2026-10-20

현재 채널의 한 메시지 변경이 전체 사용자·채널·과거 메시지 재조회로 이어지던 경로를 변경 ID 기반 동기화로 교체했습니다. SSE 연결은 유지합니다. WebSocket이나 Redis는 추가하지 않았습니다.

## 적용 순서와 계약

1. **변경분 반영**: `/api/sync`는 현재 권한을 검사하고 변경된 채널 정보, 활성 채널의 메시지, 열린 스레드의 답글만 반환합니다. 이미 불러온 과거 기록에 ID로 병합하고 `revision`으로 늦은 응답의 덮어쓰기를 막습니다.
2. **복구**: 스키마 5의 SQLite 트리거가 사용자 메시지와 GPU/예약 알림의 변경 ID를 원본과 같은 트랜잭션에 기록합니다. 본문은 복제하지 않습니다. 커서는 DB별 epoch와 순번이며 재시작 후에도 유효합니다. 20,127행 이내로 유지하고, 오래된/잘못된 커서 또는 500개 초과 변경은 스냅샷 복구를 요구합니다. 실제 제품의 삭제는 soft delete입니다. 영구 삭제 API는 제공하지 않습니다.
3. **중복 방지**: 사용자별 `clientMessageId`와 내용 지문을 메시지와 함께 저장합니다. 같은 요청은 같은 메시지를 반환하고 다른 내용으로 키를 재사용하면 409입니다. 첨부파일도 스트리밍 SHA-256으로 비교하며 중복 임시 업로드는 정리합니다. GET 및 이 계약을 쓰는 전송만 일시적 네트워크/502·503·504 오류에 한 번 자동 재시도합니다. 같은 화면에서 실패한 전송을 다시 누르면 같은 키를 유지합니다. 새로고침을 넘는 오프라인 발신함은 없습니다.
4. **연결·읽음 관리**: 화면당 SSE 하나, 동기화 요청 하나를 유지하고 60ms 동안 알림을 합칩니다. 오류 후 지수 대기와 무작위 지연을 적용합니다. 보이는 화면에서만 120~150초 보완 조회를 합니다. 숨긴 화면은 배지용 정보만 받고 복귀 때 보관한 커서로 본문을 복구합니다. 읽음 위치가 전진할 때만 저장하고 같은 사용자의 다른 세션에 알립니다. 느린 SSE는 미전달 알림 하나로 합치며 64KiB 초과 또는 30초 초과 막힘을 다음 쓰기 시 발견하면 끊습니다. heartbeat가 20초이므로 30초 정각 차단을 보장하지 않습니다.
5. **캐시·관측·용량**: 해시 이름의 웹 자산은 1년 immutable, HTML/API는 기존 재검증/no-store 정책을 유지합니다. GPU 화면은 관측 시각·오류·stale 상태까지 포함한 전체 뷰 ETag가 동일할 때만 304를 사용합니다. 화면 메모리에만 저장하고 로그아웃 후 공유하지 않습니다. 관리자 전용 `/api/admin/metrics`는 요청·오류·응답 Content-Length·지연 구간·이벤트 루프·프로세스 메모리/CPU·SSE 버퍼·원장 행 수를 제공합니다. 원문·쿼리·사용자 식별자를 기록하지 않으며 프로세스 재시작 시 초기화됩니다.

## 같은 조건의 전후 측정

격리된 임시 DB, 합성 메시지 160개, localhost Chrome 한 개로 측정했습니다. 기준 소스는 `7eb9da6c07f952fffbd9b6e201a15531ff4490a0`입니다. 표는 **디코딩한 API 응답 본문**이며 요청 헤더·SSE heartbeat·메시지 주입용 POST·CDN 압축은 제외합니다. 단일 실행이며 네트워크 지연, 다중 사용자 처리량, CPU/최대 메모리 개선율은 측정하지 않았습니다.

| 시나리오 | 이전 요청 / 응답 본문 | 이후 요청 / 응답 본문 |
|---|---:|---:|
| 조용한 채널 32초 대기 | 4 / 58,927 B | 0 / 0 B |
| 80개 기록을 본 상태에서 한 건 수신 | 4 / 58,616 B | 2 / 1,203 B |
| 과거 기록까지 160개 본 상태에서 한 건 수신 | 5 / 114,340 B | 2 / 1,218 B |
| 다른 채널에서 한 건 수신 | 5 / 114,340 B | 1 / 1,404 B |

두 번째 수신 시나리오의 응답 본문은 약 **98.9%** 감소했습니다. 32초 결과는 모든 대기 통신이 없어졌다는 뜻이 아닙니다. SSE heartbeat와 120~150초 보완 조회는 유지합니다. 실제 GPU 데이터가 15초마다 바뀌면 ETag도 바뀌므로 정상 폴링에서의 304 절감률을 주장하지 않습니다.

현재 JS는 315,875 B, 같은 `gzipSync` 방식에서 95,497 B입니다. 안정성 로직이 추가되어 이전보다 소폭 증가했습니다. 라이브러리 의존성은 추가하지 않았습니다. 기본 빌드가 최초 JS gzip 140KiB, CSS gzip 20KiB 예산을 검사합니다. 지연 로딩 청크를 향후 도입하면 전체 청크도 별도 예산에 포함해야 합니다.

```bash
# 운영 dist를 덮어쓰지 않는 검증 빌드
npx tsc --noEmit && npx vite build --outDir /tmp/lab-chat-network-preview
node scripts/audit-size.mjs --dist /tmp/lab-chat-network-preview --storage
LAB_TEST_DIST_DIR=/tmp/lab-chat-network-preview LAB_NETWORK_OUTPUT=/tmp/new-network-result.json npm run measure:network
```

측정은 임시 DB를 만들고 종료 시 제거하며 결과 경로가 이미 있으면 덮어쓰지 않습니다. 포트 4315와 Chrome이 필요합니다. 원본 측정 기록은 `.data/research/network-2026-10-20/{probe-results,probe-after}.json`이며 공개 Git에는 합성 요약과 재현 스크립트만 포함합니다.

## 설치 파일과 디스크

실행 전 논리 크기는 CI 보관 사본 약 1.50GB, 게시 설치 파일 약 790MB, 로컬 이전 빌드 약 2.07GB였습니다. 보관 사본 6개에서 **749,632,411 B(약 715MiB)**의 동일 영역을 커널이 비교한 뒤 공유했습니다. 파일별 SHA-256·inode·크기·모드·수정 시각이 유지됐습니다. 게시 중인 설치 파일, 이전 버전, 백업, DB, 첨부파일은 대상에서 제외했습니다.

이는 [Linux FIDEDUPERANGE](https://man7.org/linux/man-pages/man2/ioctl_fideduperange.2.html)의 copy-on-write 블록 공유입니다. 파일을 삭제하거나 hardlink로 합치지 않으며, 나중에 한쪽을 수정해도 다른 파일에는 반영되지 않습니다. 지원하지 않는 파일시스템에서는 실패하고 삭제 방식으로 대체하지 않습니다. 일반 `du`나 파일 크기 합은 공유 블록을 중복 계산할 수 있습니다. 위 수치는 커널이 확인한 공유 영역이며 서버 전체의 여유 공간 증가량 실측은 아닙니다. 재실행 결과에는 이미 공유된 영역도 포함되므로 누적 절감량으로 더하면 안 됩니다.

```bash
npm run audit:storage
python3 scripts/dedupe-installers.py          # 대상 확인, 변경 없음
python3 scripts/dedupe-installers.py --apply  # .data/installer-builds의 EXE/DMG만 비교·공유
```

이 검사는 이후 빌드 작업에서도 사용합니다. 사용 기록·설치 파일·백업을 보존 정책 없이 자동 삭제하는 상시 작업은 추가하지 않았습니다. Electron 런타임과 설치 파일의 다운로드 크기는 이번 변경으로 줄지 않았습니다.

## 검증 및 운영 범위

서버 테스트 43개, 브라우저 전체 17개 통과 후, 초기 기록 조회 실패 복구 시나리오를 추가하여 해당 파일 3개를 다시 통과했습니다(서로 다른 시나리오 총 18개). 서버에서는 재시작 후 커서 복구, 트랜잭션 롤백, 보관 한도, 권한 철회, 중복 전송/내용 충돌, 첨부 고아 파일 방지, 느린 스트림, 관리자 지표 권한과 GPU 304를 확인했습니다. 브라우저에서는 실제 응답 손실 후 중복 없는 재전송, 오프라인 수정·삭제·반응 복구, 다른 채널 변경의 전체 재조회 방지, 과거 기록 유지, 기존 자원·모바일·애니메이션을 확인했습니다.

디스크 공유는 별도 임시 파일에서 동일 내용·inode 보존·이후 독립 쓰기·다른 내용 거부를 검증한 뒤 보관 사본에 적용했습니다. 실제 WAN 단절, 장시간 대규모 부하, 여러 프로세스 간 이벤트 전파, Windows/macOS 네이티브 앱 재실행은 이번 검증 범위에 포함하지 않습니다. 설치 앱은 같은 웹 화면을 불러오므로 다음 화면 로드 때 변경을 사용합니다.
