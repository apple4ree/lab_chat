- TypeScript 검사와 Vite 프로덕션 빌드 통과. 기존 정적 파일을 유지한 별도 `/tmp` 빌드로 먼저 검증한 뒤 배포했습니다.
- `npm test`: 32/32 통과. 추가 7개는 실제 HTTP·SQLite를 사용한 회원/관리자 권한, 동시 승인 충돌·인접 기간, 수정 후 재승인, 버전 충돌, 점검 상태, 잔액 기록, 예약 시작·종료 및 재시작 중복 방지, 이력 입력 제한, 실제 CLI 서버 문자열 형식, 누락값·오래된 값, 캐시 병합·실패·종료 취소를 검증합니다.
- 기존 채팅·GPU 브라우저 7개 통과. 새 화면의 선택 상자 접근성 이름 문제를 수정한 뒤 새 시나리오 4개 모두 통과(최종 재실행 31.3초): 이력 다중 선택·기간·지표·수치 표, 회원 신청→관리자 검토·승인·배정→회원 취소, 비용 필터·오래된 한도·잔액 저장, 모바일 폭·회원의 관리자 버튼 미노출. 11개는 나누어 실행한 결과입니다.
- 실제 수집 서버를 읽어 대상 6개, OS 계정 집계 1개, 오래된 CLI 계정 2개, 최근 30일 API 집계 없음 확인. 실제 이력 한 GPU의 1시간/24시간/7일/30일 응답은 각각 60/301/301/300점으로 정상화했습니다. 원본 수집 서버에는 쓰기 요청을 하지 않았습니다.
- 공개 일반 사이트에서 실제 관리자 로그인 후 새 메뉴 3개와 API 200, GPU 자원 6개, JavaScript 예외 없음, 로그아웃 후 원장 API 401 확인. 예약·잔액·장비 설정의 변경 흐름은 격리된 테스트 DB에서만 실행했습니다.

변경 전후 계정 전체와 기존 메시지 행의 SHA-256이 일치하고, 양쪽 운영 DB 스키마 4 및 무결성 `ok`를 확인했습니다. 실제 운영 예약·수동 잔액에는 테스트 기록이 없습니다. 성능 부하·장기 운영·Google SSO·기존 ERP 예약 동기화·GPU 작업 실행 제어는 검증 범위에 포함되지 않습니다.

체험 공개 확인에서 샘플 이력 간격이 집계 간격보다 커 선 대신 점만 표시되는 것을 발견해 샘플 생성기를 수정했습니다. 자원 서버 테스트 7개와 새 브라우저 4개를 재실행해 모두 통과했습니다. 실제 수집 이력 처리에는 변경이 없습니다.

체험 사이트도 공유 접속 인증·샘플 로그인 후 이력 차트·예약 원장·AI 한도를 실제 Chrome에서 확인했습니다. 샘플 장비 4개, 이력 demo=true, JavaScript 예외 없음. 샘플 이력 간격 수정 후 체험 앱만 한 번 더 재시작했습니다. 근거: `.data/deploy/evidence/resources-public-demo.json`, `resources-public-demo.png`.
