# GPU 현황과 채널 알림

왼쪽 **연구 자원**에서 GPU 현황, 사용 이력, 예약·배정, AI 사용량·한도를 확인합니다. **#gpu-자원 알림** 버튼은 상태 변화와 예약 처리 소식을 받는 공개 채널을 엽니다. 예약은 일정 관리이며 실제 작업 실행·강제 종료 권한을 부여하지 않습니다.

일반 서비스는 서버 설정의 `LAB_GPU_URL`을 사용합니다. 이 설치에서는 `http://127.0.0.1:8800/api/state`를 서버가 15초마다 읽고, 브라우저에는 인증 후 정규화한 결과만 제공합니다. 클라이언트가 조회 대상 URL을 지정할 수 없습니다. 명령줄과 upstream 응답 본문·오류는 브라우저에 전달하지 않습니다. OS 사용자 이름은 개인 계정과 일치하지 않을 수 있습니다.

체험 모드는 항상 `demoGpuSource`의 샘플 장비만 사용합니다. 운영 GPU 데이터나 작업 정보는 체험 사이트에 연결하지 않습니다.

| 상태 | 기준 |
|---|---|
| 연산 중 | 유효한 최신 측정에서 사용률 > 0 |
| 메모리·작업 상주 | 사용률 0이지만 메모리 점유 또는 프로세스 존재 |
| 미사용 관측 | 사용률 0, 메모리 점유 0, 프로세스 없음 |
| 보고 중단 | 마지막 장비 보고가 180초 초과 |
| 확인 불가 | 필수 값 누락·잘못된 측정·목록에서 사라짐·중앙 연결 오류 |

미사용은 예약 가능 여부나 독점 사용을 보장하지 않습니다. 보고 중단은 장비 전원이 꺼졌다는 뜻이 아닙니다. 화면 조회 시각과 장비 수집 시각을 구분해서 표시합니다. 메모리는 원본 MiB를 GiB로 변환합니다.

## 알림과 데이터 보존

관리자 계정이 존재하면 공개 `gpu-자원` 채널과 로그인할 수 없는 `GPU 알림` 시스템 사용자를 한 번 생성합니다. 기존 동명 비공개 채널이 있으면 공개로 바꾸거나 자동 연결하지 않습니다. 새 구성원은 기존 공개 채널 가입 규칙을 따라 참여합니다. 시스템 사용자는 로그인 선택·사용자 검색·DM 대상에서 제외됩니다.

최초 관측은 기준선으로 저장합니다. 미사용 전환은 새 수집 시각으로 60초 이상 계속 확인될 때 알립니다. 보고 중단·확인 불가 전환 및 복구도 60초 유지 후 기록합니다. 순간적인 변화는 채널에 쌓지 않습니다. 일반적인 연산 시작과 상주 사이의 변화는 별도 메시지를 보내지 않습니다.

중앙 조회 실패·복구는 각각 한 번 기록하고, 실패·프로세스 재시작 사이의 시간을 미사용 확인 기간으로 합산하지 않습니다. 안정 상태·후보 상태는 `gpu_observations`, 마지막 정상화 스냅샷은 `app_meta`에 저장합니다. 알림 메시지와 안정 상태를 같은 SQLite 트랜잭션으로 기록해 재시작 후 중복을 방지합니다. 실패 시점에는 마지막 값으로 가용량을 늘리지 않습니다. UI의 서버 스냅샷도 45초 이상 갱신되지 않으면 확인 불가로 처리합니다.

단일 프로세스가 수집하고 채널 메시지가 새로 생길 때만 기존 권한별 SSE 갱신을 보냅니다. 종료 시 진행 중인 HTTP 요청을 취소하고 DB 종료 뒤 쓰기를 막습니다. HTTP는 5초 제한, 2 MiB 본문 제한, 리다이렉트 거부를 적용합니다. 최대 서버 100대·GPU 1024개를 허용합니다.

## 운영 범위

모든 `/api/resources/*` API는 세션 인증이 필수입니다. upstream을 서버 내부에서만 조회하는 것은 기존 `gpu.damilab.cc`의 공개 접근 정책 자체를 바꾸지 않습니다. 원본 서비스의 조회·수집 인증을 강화하려면 기존 ERP와 원격 수집기 연결을 함께 이전해야 합니다.

현재 스키마 버전은 6입니다. 기존 계정·메시지·예약 데이터를 보존하면서 GPU 자체 이력 테이블을 추가합니다. GPU 이력은 같은 SQLite에 저장되므로 `npm run backup`의 온라인 백업에 함께 포함됩니다. 구버전 앱은 새 DB를 거부하므로 롤백할 때는 별도 디렉터리에 백업을 복원하고 경로를 바꿔 실행해야 합니다. 백업 이후의 기록을 버리지 않도록 복구 시점을 먼저 확인합니다.

## 자체 GPU 서비스 (2026-10-21)

기존 서버 연결의 `/api/state` 측정값만 재사용합니다. GPU 화면·예약·상태 알림·이력 저장·사용 집계는 채팅 앱이 소유하며, 외부 대시보드 iframe이나 기존 GPU 이력·점유율 API를 호출하지 않습니다. 기존 수집기에서 서버까지의 연결은 유지되므로, 원격 수집기까지 교체한 것은 아닙니다. AI 한도·비용 API는 별도 연동으로 유지합니다.

`gpu-history.mjs`가 정상화된 측정값을 같은 트랜잭션에서 저장합니다. 장비의 수집 시각으로 중복·역순 보고를 거르고, 보고 중단·확인 불가·미래 시각 값은 기록하지 않습니다. 새 이력은 첫 유효 보고 시점부터 시작하며 기존 서비스의 과거 데이터를 가져오거나 비어 있는 구간을 0으로 채우지 않습니다. 화면에 수집 시작 시각을 표시합니다.

동일 장비의 유효 표본을 1분·15분 버킷에 합계/개수로 집계합니다. 1분 버킷은 7일, 15분 버킷은 90일 보존하고 시간마다 만료된 행을 제거합니다. SQLite의 비워진 페이지는 다음 기록에 재사용됩니다. 1시간·24시간 조회는 1분 자료, 7일·30일은 15분 자료를 이용하며 응답은 약 300점으로 다시 집계합니다. 24시간 계속 보고하는 GPU 하나당 최대 약 18,720개 버킷이며, 보존 경계와 정리 주기에 따른 소량의 추가 행이 있을 수 있습니다. 프로세스 명령줄·PID 이력은 저장하지 않습니다.

OS 계정 집계는 1분 이내의 연속 관측 사이에서 직전 보고의 프로세스 소유자를 GPU별로 한 번씩 셉니다. 동일 계정 프로세스가 여러 개여도 중복 계산하지 않습니다. 연결 실패·장비 누락·유효하지 않은 보고·재시작 구간은 이어 계산하지 않습니다. GPU 공유 계정 간 시간은 겹칠 수 있으며, 공용 OS 계정을 연구실 개인으로 임의 매핑하지 않습니다. 이는 프로세스 점유 추정치이며 정밀 연산량이나 과금 자료가 아닙니다. UTC 날짜별 합계를 90일 보존합니다.

## 예약 원장과 권한

일반 구성원은 전체 연구실 예약을 조회하고 본인 예약을 신청·수정·취소합니다. 관리자만 장비 설정, 검토·승인·배정·반려, 잔액 기록을 처리합니다. 예약 본문에 사용자 ID나 역할·상태를 넣어도 서버가 로그인 사용자와 `pending` 상태를 지정합니다.

상태는 `pending → reviewing → approved → allocated`이며 신청 단계에서 바로 승인할 수도 있습니다. 승인 전 반려하거나 진행 중 취소할 수 있습니다. 종료 시간이 지나면 승인·배정은 `completed`, 미승인 요청은 `expired`로 처리합니다. 배정되었거나 시작된 승인 예약은 수정할 수 없습니다. 그 외 수정 가능한 예약은 변경 후 `pending`으로 돌아갑니다. 버전 번호가 다른 쓰기는 409로 거부합니다.

한 예약은 GPU 한 개 전체를 예약합니다. 필요 VRAM은 신청 정보와 장비 용량 검사용이며 메모리 분할 배정이나 실행 격리가 아닙니다. 승인·배정 예약의 `[시작, 종료)` 구간끼리 겹칠 수 없고, 미승인 요청은 서로 겹칠 수 있습니다. 승인 시 다시 검사하므로 동시에 승인해도 하나만 확정됩니다. 기간은 최대 90일, 시작일은 현재부터 366일 이내이며 DB는 UTC epoch 밀리초, 화면은 기기 시간대, 채널 알림은 한국 시간을 명시합니다.

예약 시작·종료 처리는 30초 주기 및 예약 조회 때 수행합니다. 시작 시각을 놓치고 종료 후 재시작하면 시작 알림 대신 종료만 기록합니다. 점검 상태로 바꿔도 기존 승인 예약과 실행 중인 작업을 자동 취소하지 않습니다. 원장의 배정은 실제 GPU 접근 권한·프로세스 격리·작업 실행 상태를 보장하지 않습니다.

장비 식별은 현재 수집 형식의 `host + GPU index`이며 내부 resource UUID를 연결합니다. GPU 하드웨어 UUID가 수집 응답에 없으므로 카드 교체·번호 재배열의 동일성은 보장하지 못합니다. ERP의 A100/A6000/3090 선택지를 실제 H200/RTX 목록에 임의로 매핑하지 않았습니다.

## 조회 경계와 비용

`gpu-http.mjs`가 GPU 상태 및 별도 AI 연동의 HTTP 전송을 소유합니다. `gpu.mjs`가 GPU 측정값을 정상화하고 `gpu-history.mjs`가 저장·이력·계정별 집계를 소유합니다. `resource-source.mjs`는 별도 AI 응답과 데모 자료를 표시 필드로 변환합니다. 호출 경로는 서버 코드가 고정합니다. 수집 서버에 POST하지 않고 명령줄·인증 토큰·원시 추가 필드를 브라우저에 전달하지 않습니다. 대상 목록은 1024개, 이력 요청은 GPU 한 개당 약 300개 집계점, 화면 비교는 6개입니다.

외부 조회는 5초 제한, 응답 2 MiB, 리다이렉트 거부를 공통 적용합니다. 별도 AI 조회는 모든 쿼리 입력을 포함하는 키로 30초간 정상화 결과를 공유하고 동일 진행 요청을 합칩니다. 캐시는 최대 128항목, 동시 upstream 요청은 8개입니다. 오래된 캐시를 조회 실패 때 정상값으로 제공하지 않으며 종료 시 진행 요청을 취소합니다. GPU 상태는 기존 15초 수집, 예약 화면은 편집 중이 아닐 때 30초, CLI/API 화면은 편집 중이 아닐 때 60초 갱신합니다. 과거 GPU 이력은 조건 변경·새로고침 시 로컬 SQLite에서 조회합니다.

체험 사이트의 이력·예약·비용·한도는 샘플 소스 및 체험 DB만 사용합니다. 일반 서비스와 공유되지 않습니다.

## 자체 이력 검증 기록
