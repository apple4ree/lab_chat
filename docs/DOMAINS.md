# 관리자 접속 도메인 변경

**설정 → 접속 도메인 관리**에서 대표 주소를 변경합니다. 예: `https://chat.damilab.cc` → `https://chat.example.org`. 일반 구성원과 체험 공간은 변경할 수 없습니다. 도메인 등록·DNS 관리 권한은 별도로 필요합니다. 서버나 데이터를 옮기는 기능은 아닙니다.

## 운영 절차

1. 새 도메인을 소유하고 DNS·HTTPS·Cloudflare Tunnel을 같은 채팅 서버에 연결합니다. 기존 호스트 이름은 유지합니다. 로컬 관리 Tunnel은 설정 파일의 마지막 catch-all 앞에 새 `hostname`과 기존 `service`를 추가하고, 해당 도메인의 DNS CNAME을 같은 Tunnel로 연결합니다. 다른 계정/Zone이라면 그 Zone의 권한과 라우팅도 먼저 준비해야 합니다.
2. 관리자 화면에 새 HTTPS 주소를 입력하고 **새 주소 연결 확인**을 누릅니다. 공인 IPv4 DNS, TLS 인증서, 리다이렉트 없는 응답, 같은 workspace ID와 설정 revision을 검사합니다. 이 확인은 데이터 복사나 데이터 일치 검증을 대신하지 않습니다.
3. 10분 안에 현재 관리자 비밀번호와 기존 도메인 유지 확인을 입력해 **대표 주소 변경 적용**을 누릅니다. 적용 직전 연결을 다시 검사합니다. 새 초대 링크는 새 주소를 사용하며, 기존 주소에서도 계속 로그인·송수신할 수 있습니다.
4. 지원 앱은 시작할 때 새 주소를 확인하고 저장합니다. 실행 중에는 변경 안내를 띄우고 사용자가 이동을 선택합니다. 웹과 구버전 앱은 새 주소를 별도 브라우저 창에서 열어 초안을 보존합니다. 도메인 간 쿠키를 복사하지 않으므로 새 주소에서 다시 로그인합니다.
5. 되돌리려면 이전 주소를 새 주소 입력란에서 다시 확인·적용합니다. 기존 도메인 소유권을 유지하세요. 한 번도 이전 안내를 받지 못한 설치 앱과 기존 설치 파일의 초기 주소는 옛 도메인에 의존합니다. 기존 도메인을 폐기하려면 먼저 새 주소를 담은 설치 파일을 배포하고 모든 사용자의 전환을 확인해야 합니다.

Cloudflare 설정 참고: [공식 로컬 Tunnel 구성](https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/configuration-file/), [DNS 라우팅](https://developers.cloudflare.com/tunnel/concepts/routing/). 앱은 DNS 제공 업체의 토큰을 보관하거나 DNS를 자동 변경하지 않습니다.

## 저장과 보안 경계

- `app_meta.workspace_domains`가 workspace ID, 대표 주소, 이전 주소, revision 및 만료되는 확인 결과를 소유합니다. 기존 SQLite 백업에 포함됩니다. `LAB_ORIGIN`은 최초 생성 시의 기본값이고, 이후 관리자 설정은 재시작해도 유지됩니다. 임의의 Host/X-Forwarded-Host 헤더로 허용 출처를 넓히지 않습니다.
- `GET /api/workspace/connection`은 로그인 전에도 ID·대표 주소·revision만 제공합니다. 관리 API는 관리자 권한, 기존 CSRF 검사, 작업 직렬화, 비밀번호 재확인, 확인 결과의 사용자 바인딩과 만료, 감사 기록을 적용합니다.
- 서버 확인 요청은 HTTPS/443·루트 도메인만 허용합니다. DNS의 IPv4 결과를 검사하고 실제 연결에 고정하며 내부망/예약 IP, 리다이렉트, 8 KiB 초과 응답을 거부합니다. 쿠키나 인증 헤더를 보내지 않습니다. 현재 IPv6-only DNS는 지원하지 않습니다.
- Electron 메인 프로세스가 현재 신뢰하는 주소에서 다음 주소를 읽고, 목적지의 workspace ID·revision·대표 주소도 일치하는지 확인합니다. 렌더러는 이동 URL을 전달할 수 없습니다. 내비게이션·IPC·다운로드·권한 검사는 새 origin에도 그대로 적용합니다. [Electron IPC 보안 지침](https://www.electronjs.org/docs/latest/tutorial/security/)
- v0.1.1에는 네이티브 주소 변경 브리지가 없습니다. 웹 UI 변경만으로 이 기능을 소급 추가할 수 없습니다. v0.1.2부터 지원하며 최초 한 번 설치 파일 업데이트가 필요합니다. 정식 자동 업데이트 활성화와는 별개입니다.

## 검증 범위

`test/domains.test.mjs`는 격리 DB와 HTTP API를 통해 관리자/구성원 권한, 확인→적용→복귀, 비밀번호·만료·출처 차단, 새 초대 주소, 감사 기록을 확인합니다. 외부 대상은 주입한 응답으로 대체합니다. DNS 고정·내부망·리다이렉트·크기 제한은 전송 경계 테스트입니다.

`test/browser/domains.spec.mjs`는 격리 서버에서 실제 관리자 화면을 조작하고 미전송 초안 유지·기존 주소 사용·구버전 이동 링크를 확인합니다. Electron 연결 정책 테스트는 신뢰 체인·목적지 불일치·재시작 시 저장된 주소 사용을 확인합니다. 실제 외부 도메인 변경은 소유한 새 주소가 준비될 때 수행하며, 이 테스트는 운영 DNS 변경을 수행하지 않습니다.
