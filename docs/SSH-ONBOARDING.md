# SSH 서버 연결과 자동 수집

관리자 또는 서버 관리자는 **연구 자원 → 서버 사양 → SSH 연결·자동 설정**에서 등록된 Linux 서버에 실제 수집을 연결할 수 있다. 자원 원장의 서버 식별자를 먼저 등록한다. 기존 예약·GPU 식별자를 유지하면서 관측값을 연결한다.

## 사용 흐름

1. 등록된 서버, SSH 주소(IP 또는 DNS), 포트와 사용자명을 입력한다.
2. 조회된 SSH 공개 키의 SHA-256 지문을 서버 담당자에게 받은 지문과 비교해 확인한다. 확인 표는 사용자·서버에 귀속되며 5분 동안 한 번만 사용할 수 있다.
3. 비밀번호 또는 개인 키와 선택적 키 암호를 입력한다. 브라우저는 제출 직후 입력 필드를 비우며, 접속 정보는 Codex에 전달하지 않는다.
4. 서버가 SSH 접속과 사양을 조사하고, Codex가 30초/60초 간격 및 NVIDIA GPU 수집 여부를 판단한다. 별도 SSH 재수집에서 호스트명과 유효한 보고를 확인한 뒤에만 ‘연결 완료’가 된다.
5. CPU·RAM·디스크·GPU 관측값은 기존 자원 현황·GPU 이력·보고 중단 알림으로 연결된다. 설정 창을 닫거나 새로고침해도 진행 상태를 조회할 수 있다.

서버 키 지문은 대상 서버에서 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 등 실제 사용 중인 호스트 공개 키 파일로 확인할 수 있다. 개인 키 파일을 보내는 명령이 아니다. DNS 변경은 자동으로 다른 서버를 신뢰하게 하지 않는다. 처음 확인한 IP와 공개 키로 접속하며 IP/키가 바뀌면 기존 연결을 해제하고 다시 확인한다.

## 실제 실행 범위

중앙 채팅 서버가 OpenSSH로 접속해 함께 제공된 Python 스크립트를 표준입력으로 보낸다. 대상 서버에는 패키지·파일·서비스·cron 작업을 설치하지 않으며 sudo를 사용하지 않는다. 수집마다 재접속하므로 별도 수집 데몬이나 수신 포트를 열 필요가 없다. 중앙 서버에서 대상의 SSH 포트에 접근할 수 있어야 한다. SSH 별칭·ProxyJump·다단계 OTP 인증은 이 화면에서 지원하지 않는다.

Linux, Python 3, SSH 비밀번호 인증 또는 개인 키 인증을 지원한다. NVIDIA 정보는 해당 사용자에게 `nvidia-smi` 실행 권한이 있을 때 수집한다. GPU 프로세스는 PID와 GPU 메모리 수치만 보내고 사용자명·명령행은 수집하지 않는다. 프로세스 조회가 실패하면 GPU를 미사용으로 단정하지 않는다. 컨테이너에서는 호스트 관측값과 컨테이너 제한값을 구분하는 기존 표시를 사용한다.

Codex는 제한된 구조화 출력으로 설정만 판단한다. [공식 SDK](https://learn.chatgpt.com/docs/codex-sdk)의 `thread.run`/`outputSchema`를 사용하며 실제 접속·수집 코드는 서버 실행기가 소유한다. 새로운 임의 스크립트 생성, 패키지 설치, 서버 설정 변경, 자동 장애 복구는 실행하지 않는다. 기존 장애 분석과 별도 Codex 작업 디렉터리·지침을 사용하지만 동일하게 승인된 계정 연결을 사용할 수 있다. 모델 실패 시 설정을 중단하며 성공한 것으로 대신 표시하지 않는다. Codex는 등록할 때만 호출하고 주기적 수집에는 호출하지 않는다.

## API와 상태

모든 경로는 로그인 및 관리자/서버 관리자 권한을 요구한다. POST는 기존 세션·Origin·`X-Lab-Request: 1` 검사도 통과해야 한다. 일반 구성원은 접속 주소·계정·지문을 조회할 수 없다.

| 경로 | 요청·응답 |
| --- | --- |
| `GET /api/resources/ssh` | `plannerConfigured`, 비밀 필드를 제외한 `connections` |
| `POST /api/resources/ssh/scan` | `{host,address,port,username}` → `{ticket,ip,fingerprint,expiresAt}` |
| `POST /api/resources/ssh/connect` | `{host,ticket,trustHostKey:true,credential}` → HTTP 202, 시작한 연결 상태 |
| `POST /api/resources/ssh/:host/disconnect` | 설정 취소/주기 수집 중단, 암호화된 인증 정보 제거 |

`credential`은 `{type:"password",password}` 또는 `{type:"key",privateKey,passphrase?}`다. 자원 등록 API의 메모·안내 필드에 비밀 정보를 넣지 않는다. 상태는 `probing → planning → verifying → connected`이며 실패는 `failed`, 해제는 `disabled`다. 재시작 당시 진행 중이던 작업은 `interrupted` 오류와 함께 실패로 표시하고 자동 실행하지 않는다. 다시 입력해 설정할 수 있다.

수집 연결은 최대 8대, 설정 동시 실행은 2개, 서버 키 확인은 동시 2개/사용자당 분당 6회/대기 표 32개로 제한한다. 서버별 수집은 2개 작업자가 처리하며 한 SSH 실행은 12초, 전체 설정은 120초, 출력은 256 KiB로 제한한다. 느린 서버가 여러 대이면 표시한 수집 간격보다 실제 간격이 길어질 수 있다. 정상 보고가 없으면 현재 가용량을 표시하지 않는다. 보고 중단은 서버 전원 종료의 증거와 구분한다.

## 인증 정보와 복구

비밀번호·개인 키·키 암호는 AES-256-GCM으로 암호화하며 연결 ID를 인증 데이터로 묶는다. 키는 데이터 디렉터리의 `secrets/ssh-master.key`(0600)로 분리한다. 해당 키가 없는데 DB에 암호문이 있으면 새 키를 생성하지 않고 시작을 중단한다. `npm run backup`은 인증 정보가 있는 경우 키도 비공개 백업에 포함한다. 복원 시 DB와 키를 함께 복원해야 한다. DB와 키를 함께 읽을 수 있는 채팅 서버 운영자는 인증 정보를 복호화할 수 있으므로 이 서버와 백업의 접근 권한이 보호 경계다.

SSH는 시스템/사용자 SSH 설정·인증 에이전트·포워딩을 사용하지 않고 확인한 공개 키만 신뢰한다. 인증 정보는 명령행 인수나 모델 프롬프트에 넣지 않는다. 실행 중에는 0700 임시 디렉터리의 0600 파일과 ASKPASS를 사용하며 자식 프로세스 종료 후 삭제한다. 프로세스 강제 종료나 호스트 장애로 정리가 실행되지 못하면 운영자가 남은 `lab-ssh-*` 임시 디렉터리를 점검해야 한다. 원격 오류 원문은 저장하거나 API에 반환하지 않는다.

설정 중 역할을 회수하거나 작업을 취소하면 이후 단계를 실행하지 않는다. 이미 연결된 장비는 등록자의 역할 변경과 별개로 관리 자원이므로 계속 수집되며 현재 관리자/서버 관리자가 해제할 수 있다. 해제는 서버 원장·예약·기존 이력을 지우지 않는다. 같은 장비에 기존 로컬/고정 SSH/GPU 연결이 있으면 해당 수집 경로가 계속 동작할 수 있다.

## 검증 범위

자동 테스트는 격리 DB에서 권한·CSRF·티켓·역할 회수·취소·재시작·암호화·백업 복원·수집 통합을 확인한다. 브라우저 테스트는 서버 관리자 계정의 입력·지문 확인·상태 조회·재접속·모바일 해제를 확인한다.

실제 OpenSSH 테스트는 루프백 Paramiko 서버에서 비밀번호/암호화된 개인 키 인증, 사양 수집, 잘못된 인증 거부, 서버 키 불일치 시 비밀번호 전송 전 거부를 검증한다. Paramiko는 격리된 테스트 디렉터리에만 설치하며 앱 의존성이나 배포 파일에 포함하지 않는다.

```sh
LAB_SSH_TEST_PYTHONPATH=/path/to/isolated/paramiko node --test test/ssh-real.test.mjs
```

운영 연구 서버의 접속 주소와 인증 정보는 관리자가 화면에 입력해야 한다. 루프백 검증이나 Codex 설정 판단 성공만으로 특정 운영 서버 연결 완료를 주장하지 않는다.

이 배포에서는 사용자가 제공한 실제 Linux 서버 한 대를 공개 관리자 화면에서 연결했다. SSH 조사 → 실제 Codex 판단 → 별도 재수집 검증이 완료됐고, 이후 정기 보고 시각이 갱신되는 것과 NVIDIA GPU 2개의 분 단위 이력이 각각 두 구간 이상 저장되는 것을 확인했다. CPU·RAM·디스크와 GPU 카드가 공개 서비스에서 관측값을 표시했다. 기존 계정·메시지·예약·기존 자원 행은 배포 전 해시와 같았으며, 새 실제 서버와 GPU만 추가했다. 접속 주소와 인증 정보는 소스에 포함하지 않는다.

2026-10-21 검증에서는 전체 Node 테스트 79개와 이후 추가한 제공자 장애 분리 회귀 테스트가 통과했다. 변경 후 SSH 관련 9개 테스트와 관리자 화면·기존 서버 사양·자원 등록 브라우저 시나리오 3개도 통과했다. 실제 승인된 Codex 로그인으로 구조화된 수집 설정을 받았으며 해당 호출은 7.496초, 입력 6,226토큰·출력 94토큰이었다. 이는 한 번의 설정 판단 측정이며 수집 비용이나 일반적 지연을 대표하지 않는다.

관리자 SSH 화면은 열 때만 내려받는다. 동일 gzip level 9 기준 초기 JS는 변경 전 105,047바이트에서 105,974바이트로 927바이트 증가했고 초기 CSS는 10,106바이트로 동일하다. 추가 화면은 JS 3,203바이트와 CSS 554바이트다. 앱 런타임 의존성은 추가하지 않았다. 이 수치는 정적 파일 압축 비교이며 실제 CDN 전송량·CPU·메모리·전체 체감 속도 측정은 아니다. 화면 상태 조회는 설정 진행 중 약 3초, 완료 후 약 15초이며 숨겨진 탭에서는 중단한다.
