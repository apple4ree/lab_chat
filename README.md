# Lab Chat

연구실에서 직접 실행하는 웹 메신저의 첫 버전입니다. Slack 공개 기능 분석을 바탕으로 독립 구현했습니다. React 화면, Node.js API, SQLite 저장소를 하나의 서버에서 제공합니다.

현재 연결 주소: **https://chat.damilab.cc** (일반), **https://chat-demo.damilab.cc** (체험). 접속 정보는 서버의 `.data/deploy/접속정보.txt`, 운영 방법과 공개 주소 검증은 [DEPLOYMENT.md](docs/DEPLOYMENT.md)에 있습니다. 현재 두 서비스는 PM2로 실행 중입니다. 아래 `npm start`는 별도 로컬 실행 안내이며, 운영 중인 포트에 중복 실행하지 않습니다.

데스크톱 설치판: [앱 다운로드](https://chat.damilab.cc/#desktop-downloads) · [Windows EXE·Mac DMG 빌드 및 검증 범위](docs/DESKTOP.md).

## 1. 바로 실행

Node.js **24.15.x**를 사용합니다. 의존성과 빌드는 현재 작업 환경에 준비되어 있습니다.

```bash
cd /home/dgu/lab-chat
npm start
```

같은 컴퓨터에서 **http://127.0.0.1:4310**을 엽니다. 터미널의 `First-admin setup code`를 최초 설정 화면에 입력하고 관리자 이름·이메일·비밀번호를 만듭니다. 정해진 기본 비밀번호는 없습니다. 두 번째 구성원부터는 관리자 설정에서 생성한 초대 링크로 가입합니다.

다른 컴퓨터의 서버에 접속한 상태라면, 자신의 컴퓨터 터미널에서 아래 터널을 열고 같은 주소로 접속합니다. `YOUR_SERVER`는 현재 SSH 접속에 사용하는 호스트로 바꿉니다.

```bash
ssh -L 4310:127.0.0.1:4310 dgu@YOUR_SERVER
```

샘플 데이터로 먼저 둘러보려면 일반 서버를 종료한 뒤 다음을 실행합니다.

```bash
npm run demo
```

체험 모드는 지민·서연·도윤 계정을 선택하는 방식입니다. `.data/demo`에 저장되며 실제 임시 계정 모드의 `.data/local`과 분리됩니다. 체험 모드는 루프백 주소에서만 실행됩니다. 종료는 실행 터미널에서 `Ctrl+C`입니다.

새 환경에서는 `npm ci && npm run build`를 먼저 실행합니다. 설정이 필요하면 `.env.example`을 `.env`로 복사합니다. `npm start`가 `.env`를 읽습니다.

## 2. 현재 동작하는 범위

| 영역 | 구현한 동작 |
|---|---|
| 임시 계정 | 최초 관리자 설정 코드, 이메일·비밀번호 로그인, 7일짜리 1회용 초대, 선택적 초대 이메일 제한, 비밀번호 변경·기존 세션 취소, 로그아웃 |
| 대화 | 공개·비공개 채널, 선택 구성원 초대, 1:1 DM, 실시간 갱신, 이전 기록 페이지 탐색, 단일 깊이 스레드 |
| 메시지 | 작성·수정·삭제, 6종 반응, 고정 메시지, 구성원 멘션, 채널별 읽지 않음 표시 |
| 자료 | 20MB 이하 파일 1개씩 첨부, 권한 검사 후 다운로드, 메시지 본문·파일 이름 검색, 접근 가능한 전체 저장 기록 검색 |
| 관리 | 구성원·대화 통계, 최근 관리 기록, 일관된 DB 스냅샷과 첨부파일 백업, 데스크톱·모바일 화면 |

읽지 않음은 채널을 열어 받은 메시지까지 기록합니다. 스레드의 새 답글은 읽지 않음에 포함되며 스레드를 열면 읽음 위치를 갱신합니다. 멘션·고정 목록은 최근 100개, 메시지·검색은 80개씩 페이지로 읽습니다. 기록에 90일 같은 시간 제한은 없습니다.

실제 학교/연구실 계정 연동, 비밀번호 찾기 이메일, 사용자 정지/탈퇴, 그룹 DM, 녹음·화상회의, AI 요약, Canvas, 작업 목록, 워크플로, 외부 조직 연결, 기관용 SSO/SCIM/DLP는 아직 구현하지 않았습니다. Slack의 유료 기능 전체가 완성된 제품은 아닙니다.

## 3. 데이터와 운영

| 경로 | 용도 |
|---|---|
| `server/` | 인증, 권한 검사, 메시지 API, SSE, SQLite 모델 |
| `src/` | React 화면과 API 클라이언트 |
| `.data/local/lab-chat.sqlite` | 실제 임시 계정과 대화 기록 |
| `.data/local/uploads/` | 서버가 생성한 파일명으로 저장한 첨부파일 |
| `docs/` | 설계, 검증 범위, 화면 캡처 |

비밀번호는 salt가 있는 scrypt 결과로, 세션·초대 토큰은 SHA-256 해시로 저장합니다. 인증 쿠키는 HttpOnly·SameSite=Strict이고 `LAB_ORIGIN`이 HTTPS이면 Secure가 적용됩니다. 쓰기 요청에 같은 출처와 별도 요청 헤더를 검사합니다. 채널 멤버십으로 메시지·스레드·검색·파일·이벤트 접근을 검사하며 관리자가 모든 비공개 대화에 자동 접근하지는 않습니다.

기본 바인딩은 `127.0.0.1`입니다. 연구실에 공개할 때는 실제 도메인의 TLS 프록시와 `LAB_ORIGIN`을 함께 설정해야 합니다. [nginx 예시](deploy/nginx.conf.example)는 참고 설정이며 설치·적용하지 않았습니다. 현재 코드는 단일 Node 프로세스·단일 연구실을 대상으로 합니다. 여러 서버로 확장하려면 공유 이벤트 전송과 DB 이전이 필요합니다. 한국어 부분 문자열 검색을 위해 SQLite LIKE를 사용하므로 대량 기록에서 검색 지연을 측정하고 검색 인덱스를 도입해야 합니다.

메시지 삭제는 본문을 지우고 파일 다운로드를 차단합니다. 스레드 답글과 디스크의 첨부파일은 유지합니다. 보존 기간 정책, 영구 파일 삭제, 총 저장량 제한, 악성 파일 검사, 백업 암호화 및 자동화는 아직 없습니다. 비밀번호 재설정·정지 등 계정 운영 기능을 갖추기 전에는 소규모 내부 시험으로 사용합니다.

백업은 기존 디렉터리를 덮어쓰지 않습니다. 결과에는 계정과 대화가 들어 있으므로 관리자만 접근 가능한 위치를 사용합니다.

```bash
npm run backup -- .data/local /absolute/new-backup-directory
```

백업은 SQLite 온라인 스냅샷을 먼저 만든 후 그 스냅샷이 참조하는 첨부파일만 복사합니다. `backup-manifest.json`에 DB·첨부파일 SHA-256과 건수를 기록하며, 성공 시에만 manifest가 생성됩니다. 자동 정리로 첨부파일을 지우는 기능을 추가한다면 백업과 상호 배제를 먼저 구현해야 합니다.

복구 시험은 서버가 사용하지 않는 **새 데이터 디렉터리**에 `lab-chat.sqlite`와 `uploads/`를 복사하고, `LAB_DATA_DIR`을 그 경로로 지정해 실행합니다. 기존 운영 디렉터리에 덮어쓰지 않습니다. 백업에는 세션도 포함되므로 실제 사고 복구 시 세션 폐기 절차가 추가로 필요합니다.

## 4. 개발과 검증

```bash
npm test
npm run build
npm run test:browser
```

`npm run build`는 현재 화면에서 참조하는 JS·CSS의 gzip 용량도 검사합니다. `npm run audit:storage`는 설치 파일·빌드·의존성의 논리 크기를 함께 보고하며 파일을 삭제하지 않습니다. 통신 재측정과 안전한 보관 파일 중복 제거는 [NETWORK.md](docs/NETWORK.md)를 참고하세요.

브라우저 검증에는 `/usr/bin/google-chrome`을 사용합니다. 다른 위치는 `CHROME_PATH`로 지정합니다. Playwright가 브라우저를 추가 설치하지 않습니다. 테스트 서버는 4311·4312 포트와 별도 임시 디렉터리를 사용하고 종료 시 정리합니다. 검증 대상과 결과는 [VALIDATION.md](docs/VALIDATION.md)에 기록합니다.

화면 개발은 두 터미널에서 아래 명령을 각각 실행합니다. Vite 출처를 쓰기 요청 허용 출처로 지정해야 합니다.

```bash
LAB_ORIGIN=http://127.0.0.1:5173 npm run dev:server
npm run dev
```

## 5. 후속 구현 연결점

사용자 식별자는 내부 UUID이며 메시지가 이메일에 직접 의존하지 않습니다. `identity_provider`, `external_subject`를 미래 외부 계정 매핑에 사용할 수 있게 두었습니다. 현재 외부 인증 구현은 없으며, 실제 연구실 계정의 프로토콜을 확인한 후 인증 모듈을 교체해야 합니다. 기존 사용자 연결에는 이메일만으로 자동 병합하지 않고 검증된 외부 계정 식별자를 사용해야 합니다.

## GPU 연구 자원

왼쪽 **연구 자원**은 GPU 현황, 사용 이력, 예약·배정, AI 사용량·한도 네 메뉴로 구성됩니다. 여러 GPU의 이력 비교, OS 계정별 집계, 예약 신청·수정·검토·승인·배정·취소, 장비 담당자·점검 설정, CLI 한도, API 비용, 관리자 수동 잔액 기록을 제공합니다. **#gpu-자원**에서 상태 변화와 예약 처리·시작·종료 알림을 받습니다. 일반 모드는 `LAB_GPU_URL`의 기존 수집 데이터를 읽고, 체험 모드는 샘플만 사용합니다. 예약과 수동 잔액은 메신저 전용 원장이며 기존 ERP와 동기화되지 않습니다. 실제 GPU 작업 실행·종료 기능은 없습니다. 자세한 권한과 한계는 [GPU 기능 설명](docs/GPU.md)을 참고하세요.

운영자가 별도로 만든 로컬 아이디 계정은 로그인 화면의 **이메일 또는 아이디**에 아이디를 입력합니다. 기존 이메일 계정도 같은 화면에서 계속 로그인할 수 있습니다. 관리자 권한은 초대 생성·관리 화면·참여 채널의 메시지 삭제에 적용되며, 다른 사람의 비공개 채널·DM을 자동으로 열람하는 권한은 아닙니다.
